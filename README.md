# Visual Campus

Рабочий исходный проект по макетам Visual Campus и кейсу LOCUSCASE1: **React + TypeScript + Vite**, отдельный **Node.js + Express backend**, **Serper Search/Images**, **Gemini Vision**. Python и FastAPI не используются.

## Быстрый запуск на Windows

Нужен Node.js 22.12+ и npm. Откройте PowerShell в папке проекта:

```powershell
npm ci
Copy-Item .env.example .env
```

В `.env` заполните **только на сервере**:

```dotenv
GEMINI_API_KEY=ваш_ключ
SERPER_API_KEY=ваш_ключ
GEMINI_MODEL=gemini-3.6-flash
APP_ORIGIN=http://localhost:5173
```

`GEMINI_MODEL` — настраиваемый пример. Выберите доступную вашему Google-проекту модель, поддерживающую изображения, `generateContent` и структурированный JSON. Доступность и лимиты определяются провайдером.

```powershell
npm run dev
```

Откройте **http://localhost:5173**. Vite перенаправляет `/api` на Express, порт 3001. На macOS/Linux вместо `Copy-Item` используйте `cp .env.example .env`.

Без ключей интерфейс запускается, но поиск возвращает `SERVER_NOT_CONFIGURED`. **Демо-фотографии и поддельные ответы не подставляются.**

## Production

```sh
npm ci
npm run build
npm start
```

Express отдаёт собранный frontend и API с одного origin. Для локального production-запуска установите `APP_ORIGIN=http://localhost:3001`, затем откройте этот адрес. При публикации `APP_ORIGIN` должен точно соответствовать HTTPS-адресу сайта.

Есть Dockerfile. Передавайте секреты через переменные окружения или `--env-file`, не в Dockerfile, исходники или frontend. Разворачивайте **один Node-процесс** с постоянным временем жизни: задания и подписанные варианты выбора находятся в памяти. Для нескольких реплик нужны общий job store и общий ключ подписи; текущая версия этого не имитирует.

Это Node-приложение с `sharp` и исходящими HTTPS-запросами. Для него нужен Node/container-хостинг. Простая загрузка `dist/client` на статический хостинг не разворачивает backend. Worker-only runtime не является прямой заменой Node.

## Как устроен поток данных

1. Пользователь вводит название. Backend запрашивает Serper Search.
2. Отдельный структурированный вызов Gemini выделяет университеты **из полученных результатов**, краткое описание и ссылки на доказательную базу. При неоднозначности возвращается выбор. Выбранный вариант подписан сервером и действует 10 минут.
3. Serper Images выполняет шесть поисков: кампус, общежития, аудитории/лаборатории, библиотеки, город, спорт/студенческая жизнь. Результаты перемежаются, чтобы первые картинки не заняли одну категорию.
4. Backend проверяет адреса, robots.txt, ограничивает размер загрузки, получает изображение и доступный контекст страницы. SVG, HTML под видом картинки, недоступные и запрещённые источники пропускаются. Никаких обходов авторизации или CAPTCHA.
5. `sharp` декодирует картинку, ограничивает число пикселей, создаёт компактный JPEG для модели; SHA-256 и dHash удаляют точные и похожие дубли.
6. Gemini получает **уровень 1 JSON + реальные image bytes** и генерирует **уровень 2 JSON для одной фотографии**. Backend валидирует его через Zod.
7. Backend отбрасывает нерелевантные и низкоуверенные изображения, определяет статус проверки, переносит `reasoning` без изменений и собирает **уровень 3**.
8. Frontend валидирует ответ и выбирает экран через `switch (status)`.

Контракты находятся в `shared/contracts.ts`; HTTP и примеры — в `docs/API.md`. Контракт разрешения университета — отдельная вспомогательная операция, он не подменяет три согласованных уровня обработки фотографий.

## Что реализовано в интерфейсе

- Главная по PDF: светлый фон, тёмно-синий текст и кнопки, золотистые акценты, поиск и три шага.
- Неоднозначный запрос, отсутствие университета, API error и загрузка с фактическими счётчиками.
- Галерея пяти категорий и дополнительные фильтры; несколько выбранных тегов работают как **AND**.
- `success + data_quality: limited`, предупреждения и отсутствующие категории.
- Кликабельный источник, дата с явным различием публикации и получения.
- Spotlight с неизменённым `reasoning`, методом проверки и оценкой уверенности.
- Отмена поиска; устаревший ответ не заменяет более новый поиск.
- Адаптивная вёрстка, доступные подписи, клавиатурный фокус, нативный dialog с Escape и возвратом фокуса.
- Сломанная внешняя картинка показывает честный fallback с сохранённой ссылкой на источник.
- Сомнительную картинку можно скрыть **в текущем сеансе**. Это не отправка жалобы администратору. Контакты оператора не были предоставлены, поэтому фиктивного приёма жалоб нет.

## Значение Verified и уверенности

`verified` выставляется, когда одновременно:

- `is_relevant=true`, `confidence >= 0.85`;
- ссылка на источник относится к официальному домену, определённому из поиска;
- страница действительно доступна, после редиректов остаётся на официальном домене и содержит ссылку/путь к фотографии.

`limited_verification`: модель считает фотографию релевантной с `confidence >= 0.55`, но более строгие условия не выполнены. `source_unavailable`: изображение получено, а исходную страницу проверить не удалось. При `is_relevant=false` либо confidence ниже 0.55 карточка не публикуется.

Число confidence — **оценка модели, не статистически откалиброванная вероятность**. Официальный домен также определяется моделью по поисковым свидетельствам и может быть определён ошибочно. Совпадение пути картинки в HTML — эвристика, не доказательство владения файлом. Метод проверки прозрачно показан пользователю.

`duplicate_risk` от Gemini — только эвристика, а не доказательство дубликата; реальные дубли удаляются по хешам. dHash не гарантирует обнаружение всех обрезанных, повёрнутых или сильно изменённых изображений и может ошибаться. Reverse-image search и GPS-проверка **не реализованы и не заявляются**.

## Производительность и ограничения

По умолчанию: 30 изображений-кандидатов, независимые очереди загрузки (6 задач) и AI-проверки (5 задач), общий бюджет 90 секунд. Получение имени, поиск и проверки входят в этот бюджет. При его исчерпании показываются законченные оценки с предупреждением; если полезного результата ещё нет — ошибка тайм-аута. 30 секунд — цель кейса, **не гарантированный и не измеренный на реальных ключах SLA**.

Один поиск обычно вызывает Serper Search 1 раз, Images до 6 раз и Gemini 1 раз для идентификации + до 30 раз для изображений. Выбор из неоднозначного результата не повторяет идентификацию. Издержки и лимиты зависят от тарифов. Повторные поиски не кешируются. Все источники могут не разрешить загрузку; ограниченный профиль в этом случае нормален.

Ключи держатся на backend. Есть ограничение запросов, лимит активных заданий, защита скачивания от SSRF с проверкой всех DNS-адресов и фиксацией адреса TCP-соединения, перепроверка редиректов, лимиты размера/пикселей, валидация входа и ответа, CSP и отсутствие HTML-инъекции из результатов. `TRUST_PROXY_HOPS` задавайте только согласно реальной доверенной proxy-цепочке.

Перед масштабным публичным запуском потребуются внешний лимит расходов/антиабьюз, централизованное хранилище заданий и наблюдаемость. Текущая версия подходит для запуска одного экземпляра и хакатонного сценария.

Публичность изображения и разрешение robots.txt **не дают лицензию на повторное использование**. Оператор должен проверить условия API и источников. Изображения не сохраняются постоянно и не включены в этот проект; при показе браузер обращается к исходному хосту. Недоступные источники не обходятся. Задания удаляются из памяти через 10 минут; политика хранения у Gemini, Serper и хостинга отдельная.

## Проверка

```sh
npm test
npm run build
```

Для браузерных тестов после сборки:

```sh
npx playwright install chromium
npm run test:ui
```

Проверено при подготовке проекта: production-сборка, 23 серверных/контрактных теста и 2 браузерных сценария на desktop и мобильной ширине. Браузерные сценарии галереи используют явно обозначенные тестовые ответы; реальный поиск без API-ключей не проверялся. Изображение главного экрана для ознакомления находится в `docs/preview-desktop.png`.

Тесты покрывают контракты, SSRF-адреса, обманные домены, настоящую обработку/сравнение изображений, статусы проверки, перенос reasoning, категорию/теги, подписи выбора, ошибки провайдеров, ограниченные результаты, редиректы и HTTP lifecycle.

В автоматических тестах используются явно обозначенные fixtures; они **не подключены к production-поиску**. Проверки с реальными Gemini/Serper ключами, качество выдачи и фактическое время на неизвестном университете нужно выполнить после настройки ключей.

Ручной сценарий:

1. Найти университет полным именем и проверить источник нескольких карточек.
2. Найти короткую аббревиатуру вроде MIT; при нескольких подтверждённых кандидатах выбрать нужный.
3. Найти неизвестное название, например Xyzabc University.
4. Найти небольшой университет и проверить честный limited-data результат.
5. Проверить категории, комбинацию тегов, spotlight, Escape и мобильную ширину.
6. Проверить квоту/ошибочный ключ: ошибка должна быть явной, без фиктивной галереи.
7. Ввести новый университет, которого не было в демо, и измерить время.

## Структура

| Путь                  | Назначение                                             |
| --------------------- | ------------------------------------------------------ |
| `client/`             | React UI и адаптивные стили                            |
